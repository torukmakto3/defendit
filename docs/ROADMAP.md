# Roadmap

Status of Defend It on `main` as of 22 Oct 2026. #2, #3 (including #13 and #14), are merged. #1 is closed.

## Shipped

- **Secure foundation** ([#2](https://github.com/torukmakto3/defendit/pull/2)). Email-link accounts, encryption at rest, process-and-purge, minimal receipts, zero-retention model calls. Postgres when `DATABASE_URL` is set (raw SQL through postgres.js); SQLite locally.
- **Titleblock redesign** ([#3](https://github.com/torukmakto3/defendit/pull/3)). Day and night themes, robot companion, PDF certificate and PNG stamp, Learn projects and flashcards, LiveKit voice for Hard and Expert (`agent/`). Tokens in `DESIGN.md`.
- **Interview reliability and rubric v0.4** ([#13](https://github.com/torukmakto3/defendit/pull/13)). Schema-checked model output, one repair turn, deadlines, idempotent answer saves, a fixed question blueprint, median grading, one follow-up then a flagged receipt. Rubric `defend-it-rubric-v0.4`. `npm run calibrate` and `npm run soak`.
- **CI** ([#14](https://github.com/torukmakto3/defendit/pull/14)). Every pull request runs install, typecheck, lint, tests, and mock-mode smoke on Node 22.
- **Pinned grading council** ([#15](https://github.com/torukmakto3/defendit/pull/15), [#7](https://github.com/torukmakto3/defendit/issues/7)). `LIQUID_COUNCIL_MODELS` is a comma-separated list of pinned models. A deployment refuses to start and refuses to grade when any member is `*.auto` or there are fewer than 2. Each stored grade keeps the model id, temperature, and seed.
- **Per-defense token and cost tracking** ([#8](https://github.com/torukmakto3/defendit/issues/8)). Each model call stores prompt tokens, completion tokens, and USD cost. A defend session total includes every call on that defense. The admin list and session page show the total and flag a defense over `SESSION_BUDGET_USD` (default $3).
- **Google sign-in** ([#16](https://github.com/torukmakto3/defendit/issues/16)). Authorization code with PKCE and state. The ID token is verified (issuer, audience, signature) and `email_verified` must be true. The verified email opens the same `users` / `auth_sessions` rows and `di_session` cookie as a magic link, matched case-insensitively, including `ADMIN_EMAILS`.
- **Grader settings on the receipt** ([#25](https://github.com/torukmakto3/defendit/issues/25)). The signed receipt records each grader's model, temperature, and seed. `/r/[id]` and `/verify/[id]` show them. Older receipts that only have model ids still verify and render.
- **Optional warmer interviewer voice** ([#28](https://github.com/torukmakto3/defendit/issues/28)). `TTS_PROVIDER=xai` speaks with xAI Grok TTS, voice Ara, through LiveKit Inference. Unset or `deepgram` keeps Aura-2 Thalia. Comparison and the Muse Wonder finding are in `docs/voice-evaluation.md`.
- **Interview start and grading latency** ([#27](https://github.com/torukmakto3/defendit/issues/27)). Per-stage timings on the admin session. The council runs in parallel, each member on its own timeout, and token accounting is flushed once after the graders return. The first question is phrased while the upload is saved. The interview shows how many graders have finished.
- **Learn after the file text is deleted** ([#35](https://github.com/torukmakto3/defendit/pull/35)). Dashboard Workspace for a creator opens that deliverable's Learn flashcards. The deck is cached, encrypted like other card fields, just before document text is deleted (defense completion, or the 72-hour text timer). Learn serves that deck afterwards. A finished defense with no saved deck asks the creator to upload the same file again. Raw document text is not kept any longer.
- **First flashcard while the rest load** ([#36](https://github.com/torukmakto3/defendit/issues/36)). Learn streams card 1 from the pinned `FLASHCARD_MODEL` and appends the rest as later batches finish. A stored deck renders with no model call. Caching that deck before the text wipe does not hold the receipt. Time to first card is logged as `stage: first_card`.
- **Browser tests for interview retries** ([#18](https://github.com/torukmakto3/defendit/issues/18)). Playwright, in mock mode, drives the text defense to a signed receipt. It retries a failed question fetch, a dropped answer (no second row), a 409 on a different resubmit, a failed grade, and a slow council. A reload continues the open question, or grading when every answer is already stored, and that reload does not take a second credit hold. A cut-off start stream still reaches the next question, and a voice error falls back to typed answers. A challenge link is claimed, uploaded, defended, and receipted, and a spent beta allowance shows the out-of-credits screen. The Browser CI job is separate from Check and caches the browsers.
- **Integrity signals survive a reload.** Paste and focus-loss totals are stored on the defend session and cannot be lowered by a later report. They are sent with each answer and through `POST /api/sessions/defend/signals`. The interview clock uses `sessions.started_at`. `GET /api/sessions/defend/state` returns that start time and the totals with `Cache-Control: no-store`. The signed receipt uses the stored totals.
- **Per-plan cost cap** ([#38](https://github.com/torukmakto3/defendit/issues/38)). Consumer defenses cap at `SESSION_BUDGET_USD_CONSUMER` (default $0.75) and enterprise at `SESSION_BUDGET_USD_ENTERPRISE` (default $3). The cap is checked, including in-flight calls, before each model call. Optional calls are skipped, required calls move to the cheap model, and a defense still receives a graded receipt. When that grade is the single cheap model, the receipt names it and marks it as a budget fallback. Voice cost is LiveKit minutes reported by the agent. The admin list shows total, LLM vs voice, p50/p90/max, and how many defenses were capped. `getCostTier` is the stand-in until plans land.
- **Shareable receipt cards.** `/r/[id]` emits Open Graph and Twitter `summary_large_image` metadata and a 1200×630 image drawn by the same helper as challenge cards (`renderOgCard`). The headline uses the tiers in `src/lib/challenge-tier.ts` (Strong at 85, Defended from 70 to 84, otherwise Still sharpening). A challenge result keeps the visibility the defender stored: public shows the score, score-hidden shows the tier and not the number, and private is a generic card. A sample demo (`payload.demo.sample`, read through `getReceipt`) says "Sample demo · Not a credential" and shows no score. The image URL includes the visibility so a change misses the cache.
- **Live calibration follow-up** ([#19](https://github.com/torukmakto3/defendit/issues/19)). The 2026-10-22 Liquid council run (gpt-oss-120b, deepseek-v3.2, llama-3.3-70b-instruct) is in `docs/calibration/2026-10-22-live.md`. The grader timeout default is 55s, inside the 120s defend route. A grader retries once on 503 overloaded and 404 model_not_found, and that retry still goes through the per-defense cost cap. An all-non-answer defense scores zero without calling the council, and that receipt is labeled `rule:non-answer` rather than a council model. The grading prompt is rubric `defend-it-rubric-v0.5`. `GRADER_TIMEOUT_MS` is clamped near 59s, and a budget-fallback grader stops 10s before the route deadline. Calibration uses authored strong answers and an on-topic vague weak set. `npm run calibrate` refuses a live router or a council under two pinned models, reuses one claim map per fixture, and prints per-model scores, disagreements of 2+ rubric levels, latency, and cost.
- **First-party funnel analytics** ([#46](https://github.com/torukmakto3/defendit/pull/46)). `analytics_events` counts a 7-day beta funnel by event name: landing, sign-in, defense, Learn opens, receipt share, and the challenge steps. No third-party tracker, no analytics cookies, no IP or user agent, no account, session, receipt, or challenge id, and no document content. Anonymous visits honor Do Not Track and Global Privacy Control. Events older than 90 days are deleted by the purge job. `/admin` shows the last 7 days and the conversion between steps. Challenge steps are recorded from `src/lib/challenges.ts` (no account, session, receipt, or challenge id). `GET /api/stats` (Bearer `STATS_TOKEN`) returns counts only for the daily dashboard. Unset `STATS_TOKEN` answers 404; a wrong token answers 401. Beacon and stats limits use `ipLimitKey`. When `ipHash` is null those per-address buckets are skipped, and the beacon still enforces the global cap. `rate_limits` does not store the address. `/privacy` describes the event row. Sample demos — request kind `demo`, an email ending in `@demo.defendit.invalid`, or a receipt `payload.demo` — stay out of sign-ups, defenses, pass rates, receipts, and average cost, and are reported as `demo.started`, `demo.completed`, and `demo.budget_cents`. A defense with kind `demo` is not written, so it stays out of the `/admin` event steps. `ANALYTICS_ENABLED=false` turns recording off.
- **Tab icon** ([#55](https://github.com/torukmakto3/defendit/issues/55)). Placeholder while the logo is on hold: a plain D in day `blueprint` on a day `ink` tile, both from `src/app/globals.css`. `src/app/icon.svg` is the source. `npm run brand-icon` writes `favicon.ico` (16/32/48), `icon.png` (512), and an opaque `apple-icon.png` (180). The header no longer shows the Rev B label.

## Next

- **No-login sample demo.** Homepage button "Try it with a sample file". A visitor finishes a 3-question text defense on a bundled README or design memo and gets a signed receipt marked as a demo, not a credential. Answers follow the normal wipe, on a 24-hour timer, and the receipt is left out of dashboard, Learn, and admin lists. Each demo counts `BETA_DEFENSE_EUR` against its own lifetime `DEMO_BUDGET_EUR` cap (default 20) on `credit_budget` id `demo`, and does not spend the shared `BETA_BUDGET_EUR` row. `DEMO_PER_IP_PER_DAY` (default 3) and `DEMO_DAILY_CAP` (default 20) limit starts. The IP is stored only as the shared keyed hash (`IP_HASH_SALT`, or `DEMO_IP_SALT` when that is unset) for that window. Without a usable salt the sample returns 503 and does not start. `DEMO_ENABLED` defaults off; only `1` or `true` turns the path on, and the homepage sample section stays hidden until then. The two samples ship with their claims and questions, so a demo does not call a model before the budget charge. Social previews reuse the share card: a sample says "Sample demo · Not a credential", omits the score, and is noindex.
- **Terms, how it works, and FAQ.** Public pages for the beta grant, the price list, refunds as wallet credit, what a receipt is, challenge opt-out, and the file clocks. `/privacy` is a separate change.
- **Plans, credit ledger, and the one-time beta grant** ([#39](https://github.com/torukmakto3/defendit/issues/39)). One wallet. A defense and a challenge each cost 1 credit. The first time any signed-in account needs credits, it gets `BETA_DEFENSE_CREDITS` defenses (default 3), 2 challenges, and 3 Learn slots, once. Stripe stays off behind `BILLING_ENABLED=false`. A further free defense is refused, and the global beta budget can refuse a sponsored defense sooner. Each sponsored defense counts €0.70 (`BETA_DEFENSE_EUR`), about the $0.75 consumer cap, against the €150 budget. Starting another defense refunds an unfinished hold that is already attached to an in-progress session, or an unattached hold older than two minutes. A second start while the first question is still being phrased does not take that fresh hold back. A purged or retention-expired Learn project does not keep its slot.
- **Challenge links, beta only, flag off** ([#37](https://github.com/torukmakto3/defendit/issues/37)). `CHALLENGES_ENABLED` (default off) turns on free sponsored defenses badged "Sponsored by DefendIT". The defender chooses public, tier-only, or private; a public result is the receipt at `/r/{id}`. Tiers are Strong (85+), Defended (70–84), and Still sharpening (under 70). The creator cannot claim their own link. Creating a challenge holds the challenger's challenge credit through the ledger in [#39](https://github.com/torukmakto3/defendit/issues/39). A finished defense consumes that credit whatever is published. Decline, expiry, and revoke refund it. A challenge defense does not spend the defender's defense credit. A beta challenge defense reserves `BETA_DEFENSE_EUR` on the ledger's `BETA_BUDGET_EUR` (default 150) when the defense starts. Decline, expiry, and revoke release that reservation. Completing a challenged defense grants the onward challenge credit. `BILLING_ENABLED` stays off: no Stripe calls and no spending. The global daily cap is still provisional.
- **Stripe Checkout in test mode** (off by default). `BILLING_ENABLED` is the only switch. While it is off, `/pricing` is hidden and Stripe routes answer 402. It does not change the beta grant or the €150 budget. A live key (`sk_live_` or `rk_live_`) or `STRIPE_MODE=live` is refused by the checkout and portal routes unless `STRIPE_ALLOW_LIVE=true`. The rest of the site still starts. Prices resolve by lookup key, not price-id env vars. Checkout sells pay-as-you-go, packs, Pro, and Team. Enterprise is a quote. Monthly plans grant on `invoice.paid` only. Yearly Pro (€99) grants month 0 on that invoice and refills to 10 defenses, 5 challenges, and 10 Learn projects each month from the purge cron, with the same refill key, and unused monthly defenses and challenges do not roll over. The overage meter is not created; extra Enterprise defenses are invoice items. See `docs/payments.md`.
- **Real email sign-in via Resend** (`RESEND_API_KEY`, `EMAIL_FROM`). Blocked on a sending domain. Google covers production sign-in until then. Preview can still use on-screen links.

## Known risks

- **On-screen dev links.** Local dev shows the sign-in URL on the page. A preview deploy can too, with `AUTH_DEV_LINKS=1` and an allowlist. `VERCEL_ENV=production` never returns that URL, even if `AUTH_DEV_LINKS=1`. Admin addresses never get one. Anyone who can open a preview with the flag on can still use a link for an allowed address.
- **Slow council tail.** On the 2026-10-22 run, llama-3.3-70b-instruct was the slowest grader (p90 about 46s, max about 86s) and the widest on strong answers. The 55s default covers that p90. Calls past 55s still drop that member.
