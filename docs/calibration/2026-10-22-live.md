## Setup
- **Code:** `main` @ 357f923 (read-only clone). Same code path as `scripts/calibrate-grading.ts` (`extractClaims` → `buildInterviewPlan` → `gradeSession` → `scoreDefense`), run through a local instrumented harness that adds per-model scores, latency and cost.
- **Provider:** Liquid Inference, host `router.inference.ai.exchange`.
- **Claims:** `liquid.auto`, which served `glm-5.3-flash` on every call.
- **Council:** `gpt-oss-120b, deepseek-v3.2, llama-3.3-70b-instruct`, temperature 0, seed 0, rubric `defend-it-rubric-v0.4`, difficulty standard, 5 probes per defense.
- **Runs:** 6 runs × 3 fixtures (investment-memo, short-essay, technical-note) × 5 answer sets = 90 defenses, plus 2 probe defenses. 451 model calls.
- **Repetitions:** the default `CALIBRATE_RUNS` is 8; I used 6 for wall-clock time, not cost. Each defense takes about 30–60 s.
- **Timeouts:** raised to `GRADER_TIMEOUT_MS=120000` and `LLM_TIMEOUT_MS=59000`, so each call is capped at 59 s, the code's internal half of the 120 s route budget. At the 20 s default, the first probe defense failed: all 3 graders timed out (see Reliability).

## Notable failures and examiner reasoning
- **The template "strong" answer is not strong to real graders.** It quotes the claim and adds a generic sentence. The council reads it as a restatement:
  - deepseek-v3.2 (0/100, short-essay): *"does not engage with the counterfactual question about halving the inputs, instead providing a generic, non-responsive statement."*
  - deepseek-v3.2: *"restates the claim but does not explain how the figure was derived, and the reasoning is a generic template."*
  - gpt-oss-120b (the most generous at 75): *"repeats the claim verbatim (accuracy 4) and gives a generic reason…"*

  So the ≥80 target fails because of the fixture, not because the graders are miscalibrated.
- **gpt-oss-120b is erratic on accuracy for good answers.** It once scored accuracy 1 and reasoning 1 while its own reason says *"correctly identifies the fixed max_attempts setting as the key factor and explains how changing it would break the at-most-8 guarantee"* (technical-note).
- **llama-3.3-70b scores accuracy 1 on answers it calls accurate:** *"accurately explains the claim and provides additional context"* scored accuracy 1, reasoning 1, transfer 4, ownership 4 (short-essay). It is the main source of the authored set's 72–100 spread.
- **gpt-oss-120b gives the vague set a flat 0** (*"does not address the claim, figures, or any reasoning"*), stricter than the rubric's level 1 for right-topic answers. deepseek gives 25 (*"engages the topic but does not match the claim's figures"*). The median still lands at or below 19.

## Reliability and latency
- **Claim extraction:** p50 4.8 s, p90 7.6 s.
- **Grader calls, p50 / p90 / max:**
  - gpt-oss-120b: 11.0 / 31.9 / 58.6 s
  - deepseek-v3.2: 22.5 / 34.8 / 46.2 s
  - llama-3.3-70b: 32.6 / 46.2 / 85.6 s
- **Grade step per defense (council in parallel):** p50 31–38 s; 59 s on authored transcripts, where one member hit the 59 s per-call cap.
- **180 of 251 successful grade calls took longer than 20 s.** That covers 82/84 llama calls and 62/89 deepseek calls. With the code default `GRADER_TIMEOUT_MS=20000`, most defenses would lose 2 of 3 graders and fail. **Production is at risk unless prod sets a higher `GRADER_TIMEOUT_MS`.**
- **Errors:** 15 calls hit the 59 s cap (mostly gpt-oss on authored answers). There were also 3 × `503 overloaded` (all 3 members at once), 1 × `404 model_not_found` on `gpt-oss-120b` (transient), and 3 defenses lost (2 authored, 1 bad).

## Cost
- **Actual Liquid charges:** $0.281 total, against a $2.25 cap. Graders $0.174, authored-answer generation $0.107, claims $0.0008.
- **Per defense (claims plus 3 graders):** about $0.002. The pre-run estimate was about $0.006.
- **Average tokens per grader call:** about 1.7k in and 0.6–0.8k out.

## Recommendations
1. **Timeouts (urgent, prod):** set `GRADER_TIMEOUT_MS` to about 55000 (or change the code default) and check prod's value before the CHALLENGES_ENABLED launch. Consider swapping `llama-3.3-70b-instruct` for a faster pinned model; it is the slowest member and the widest on strong answers.
2. **Calibrate fixtures:** replace the template "good" answer with authored strong answers per fixture, either checked into `fixtures/calibration/*.answers.json` or generated as above. Add the on-topic vague weak set. Then ≥80 and ≤30 test the council instead of a template and a regex.
3. **Calibrate script:**
   - refuse a live run when `gradingCouncilProblem` reports a router or a council under 2 (locally, it silently falls back to `liquid.auto`);
   - pin the claim map per fixture so runs vary only by grading;
   - print per-model scores, disputed probes, latency and cost.
4. **Rubric prompt:** state that accuracy is judged on the answer's content and not on quoting the source wording. Add one worked example per level. This should help with gpt-oss and llama scoring accuracy 1 on correct answers.
5. **`gradeSession`:** when every turn is a `detectNonAnswer` hit, return zero grades without calling the council. That saves 3 calls and about 30 s per all-refusal defense.
6. **Retry:** retry once on `503 overloaded` and `404 model_not_found` before dropping a member.
